# GLOSSARY.md

Source: handoff Section 5. Use these terms consistently in code, data, prompts, and UI — do not
invent synonyms.

**Signal** — An observed change or condition that might create economic value (demand
acceleration, CPC movement, a new regulation, a stockout, a recurring feature request, a buyer
payout change, a competitor exit, a seasonal event, a cost-reducing API). Not yet an opportunity.

**Market** — A domain in which buyers and sellers exchange value. May be broad (local home
services) or narrow (booked appointments for one service in one geography).

**Marketplace** — A venue, network, exchange, platform, or relationship through which a
monetizable output can be converted to cash (affiliate/CPA network, pay-per-call network, lead
exchange, freelance marketplace, app marketplace, e-commerce marketplace, direct buyer network, ad
network, sponsorship marketplace, data marketplace, software marketplace, James's own buyer
roster). Must record acceptance rules, economics, integration method, payout delay, and
verification date.

**Exit Path** — The concrete mechanism by which a proposed output becomes money. An opportunity
without an exit path is an idea, not an executable opportunity.

**Opportunity** — An evidence-backed proposition that a specific action can convert defined
resources into expected financial value through a known or testable exit path. Must include:
signal, target buyer/audience, offer/output, exit path, evidence, economics, required
capabilities, time to feedback, maximum downside, confidence/uncertainty, and a proposed mission.

**Hypothesis** — A falsifiable statement about why the opportunity should work.

**Mission** — The unit James approves and assigns to a cohort. A scoped assignment with an
objective, owner/cohort, budget, time window, inputs, required tools, expected artifacts,
experiments, success/scale/pause/kill rules, reporting cadence, and permission envelope.

**Experiment** — A bounded test inside a mission designed to validate one or more hypotheses.

**Revenue Engine** — A repeatable mechanism that converts inputs into revenue (paid traffic →
affiliate conversion, search content → affiliate conversion, lead capture → buyer payout, software
usage → subscription, data alert → subscription, content distribution → sponsorship, product
listing → gross margin).

**Asset** — Anything created by a mission that retains value: dataset, code, prompt, connector,
domain, landing page, content, audience, buyer relationship, ad-account learning, creative,
playbook, model, brand, lawfully-collected customer list, calibration data.

**Cohort** — A functional group of workers, tools, and permissions assigned to one or more
missions.

**Agent** — A role-based decision process. May be a frontier model, smaller model, deterministic
program, or hybrid. "Agent" is never synonymous with "one LLM conversation."

**Legionary** — A visual capacity unit in the dashboard. Does not have to map one-to-one to a
compute process.

**Knowledge Yield** — The reusable decision value produced by a mission, especially when financial
return is low or negative.

**Liquidity** — How reliably and quickly an output can be converted to cash at an understood price
and acceptance rate.

**Capability** — An abstract action the system can perform, e.g. `buy_traffic`, `publish_product`,
`route_lead`, `create_landing_page`, `measure_conversion`.

**Connector** — A concrete implementation of a capability for a specific platform, API, browser
workflow, or internal service. The system reasons about capabilities and swaps connectors as
platforms change.
